# Week 9 — A readable actor–critic in MuJoCo

Train a neural actor and a separate value critic on Gymnasium's standard
`InvertedPendulum-v5`. This is synchronous advantage actor–critic (A2C), implemented
in PyTorch. PPO and SAC are not used.

## Setup

From the repository root, using Python 3.12 on Linux:

```bash
python3 -m venv /tmp/robotics-week09-venv
source /tmp/robotics-week09-venv/bin/activate
python -m pip install 'torch==2.14.1' --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r week09_actor_critic/demo/requirements.txt
```

The CPU wheel avoids a CUDA installation. PyTorch, Gymnasium, MuJoCo, NumPy, and
Matplotlib are pinned. Use a working Matplotlib desktop backend (Tk or Qt) for the
viewer; if neither is installed, install a Qt backend with `python -m pip install PyQt5`.
Headless training/evaluation/plots do not require a desktop or OpenGL rendering.

The viewer uses MuJoCo offscreen EGL rendering displayed inside Matplotlib. EGL
needs a compatible graphics driver or Mesa installation; this route worked on the
development desktop where the native MuJoCo viewer previously failed.

## Run the prepared classroom comparison

```bash
python week09_actor_critic/demo/watch.py
```

The two included checkpoints are generated by this implementation, not downloaded
policies. The viewer starts paused on the initial policy and test seed 20000.

- **Play / Pause:** run or pause physics and deterministic policy inference.
- **initial / trained:** switch policy and reset to the same seeded initial state.
- **Restart:** reset the same episode; retain pause status and policy choice.
- **Next episode:** move through the 20 fixed test seeds; retain pause status.
- Close the window to stop and release the rendering context.

The readout shows controller, test seed, steps, undiscounted episode return, current
pole angle, and the critic's estimate at the current observation. V is discounted
expected return under the training policy, not elapsed reward; deterministic viewer
behavior can differ from the stochastic policy the critic learned about.

Watch the initial policy fail, then switch to trained on the same start. The camera
settings are identical. Evaluation uses `3*tanh(mean)` and never updates weights.
It does not sample exploratory actions or use an epsilon parameter.

## Task and algorithm

Observation: `[cart_position, pole_angle, cart_velocity, pole_angular_velocity]`.
One continuous command lies in [−3,3]. The standard model determines how the actuator
applies that command; the task/reward are not modified.

Gymnasium 1.3.0 implementation, verified locally:

- Reward 1 if the state after stepping is healthy; reward 0 on failure.
- Termination if any observation is nonfinite or `abs(pole_angle) > 0.2` radians.
- The TimeLimit wrapper truncates after 1,000 steps.

The actor and critic have separate 64–64 tanh MLPs. The actor learns Gaussian mean
and state-independent log standard deviation (numerically bounded to [−5,2]).
Actions are `3*tanh(z)`. Log densities include the transformation's Jacobian and
scale. Sampling uses a detached latent action; the actor update uses a score-function
gradient at that fixed sample, not a pathwise derivative through the simulator.

Every update uses five steps from eight environments (40 transitions). A reverse
pass builds discounted return targets. True termination gives zero bootstrap;
truncation uses the final observation's value before reset. Returns never cross resets.

```text
advantage = target − V(state)
actor_loss = −mean(log_probability × advantage.detach())
critic_loss = mean((V(state) − target.detach())²)
loss = actor_loss + 0.5 × critic_loss
```

One RMSprop update per fresh batch: learning rate .0007, gamma .99, gradient norm
limit .5, no entropy bonus, replay buffer, or repeated optimization of old data.
Defaults and dependency versions are saved with each run.

## Reproduce training and evaluation

Prepare full training before class:

```bash
python week09_actor_critic/demo/train.py --seed 7 --output /tmp/week09-seed7
python week09_actor_critic/demo/train.py --seed 0 --output /tmp/week09-seed0
python week09_actor_critic/demo/train.py --seed 1 --output /tmp/week09-seed1
python week09_actor_critic/demo/compare.py --runs /tmp/week09-seed7 /tmp/week09-seed0 /tmp/week09-seed1 --output /tmp/week09-comparison
```

Each run defaults to 250,000 transitions. It saves an initial checkpoint, checkpoints
every 25,000 transitions, a validation-selected `best.pt`, settings, episode returns,
update metrics, validation history, and elapsed time. Existing nonempty run directories
are rejected to avoid overwriting experiments. Seeds 7/0/1 took approximately 64/58/69
seconds respectively in the measured CPU runs, some running concurrently; timing will
vary on other machines.

For a longer budget, run `--steps 1000000 --output /tmp/week09-seed7-long`.
This reruns from the seeded initialization for a longer budget; it is not exact resume.
Steps must be a multiple of 40. No extension was needed for the included seed-7 demo.

Validation uses seeds 10000–10009, every 25,000 transitions, selecting the earliest
checkpoint with the highest mean validation return. Test seeds 20000–20019 are
reserved for final comparisons. Training environment streams use distinct seeds
starting at `100000 + training_seed*100`.

Evaluate any selected checkpoint without graphics:

```bash
python week09_actor_critic/demo/evaluate.py
python week09_actor_critic/demo/evaluate.py --checkpoint /tmp/week09-seed7/best.pt --output /tmp/week09-test.json
python week09_actor_critic/demo/watch.py --initial /tmp/week09-seed7/initial.pt --trained /tmp/week09-seed7/best.pt
```

No training environments or random action streams are advanced during evaluation.
The critic is not needed to choose deterministic actions; it is displayed to help
explain the architecture.

## Measured results and classroom fallback

All three runs used 250,000 training transitions. Test episodes share the same starts
for initial and selected policies:

| Training seed | Initial mean steps | Selected mean steps | Reached 1,000 steps | Selected checkpoint |
|---|---:|---:|---:|---:|
| 7 | 28.4 | 1000.0 | 20/20 | 100,000 |
| 0 | 28.0 | 220.2 | 0/20 | 25,000 |
| 1 | 27.9 | 1000.0 | 20/20 | 75,000 |

A failed episode's return is one less than its length because the failure step gives
zero. A healthy 1,000-step episode has return 1,000. See [exact results](classroom/results.json).

- [Validation curves, test comparison, and matched angle traces](classroom/comparison.png)
- [Stochastic training curves](classroom/training.png)
- [Checkpoint provenance and run settings](classroom/settings.json)

Seed 0 demonstrates genuine variability and deterioration after its best checkpoint;
more training did not monotonically improve its performance. The supplied seed-7
checkpoint was chosen by validation, not by test performance. These 20 small perturbations
are not a claim of robustness to large disturbances or changed dynamics.

The original training runs used system Matplotlib 3.6.3, recorded in the provenance.
The pinned setup uses Matplotlib 3.10.8 for Python 3.12 wheel availability; the algorithm
and viewer tests were also checked with that version. Plotting does not affect training.
